## Draft template
Copy one block per localization per draft version. Keep the current live values next to the draft so the diff is obvious.

```markdown
### Draft <ID> — <localization> (storefronts: …) — v<n> — YYYY-MM-DD
**Status:** Draft | In review | Approved (not submitted) | Submitted on YYYY-MM-DD by user | Rejected
**Task:** tasks/…/<id>.md

| Field | Limit | Live (date checked) | Draft | Length |
|---|---|---|---|---|
| Name | 30 chars | | | |
| Subtitle | 30 chars | | | |
| Keywords | 100 bytes | (user-provided) | | |
| Promotional text | 170 chars | | | |
| Description | 4000 chars | link to live copy | see below | |

**Screenshot narrative** (real screens only; caption + screen per slot, up to 10):
1. Caption — screen — feature it shows (verified? Y/N)

**Claims used and their verification:** each claim → source (build, listing, user confirmation).
**Reasoning:** why each change, linked to evidence rows in keyword/competitor research.
**Risks:** e.g. losing rank on terms dropped from keywords; review-guideline issues; claims needing confirmation.
**Measurement plan:** primary metric (e.g. App Store search conversion for that territory from App Store Connect), baseline period, comparison period, confounders (seasonality, other releases, other storefront changes), minimum observation window. Or: Product Page Optimization test if eligible.
**Approval needed:** submit metadata for <localization> — not yet requested / requested on … / granted on … by user.
```
